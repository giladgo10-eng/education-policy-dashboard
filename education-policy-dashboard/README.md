# דשבורד מדיניות החינוך בישראל (education-policy-dashboard)
### תמונת מצב מערכת החינוך לקראת תשפ״ז | מצעי מפלגות | מבחן ביצוע ממשלתי

ברוכים הבאים למאגר המידע והתשתית המחקרית של פרויקט **education-policy-dashboard**.
פרויקט זה נועד להציג בצורה אינטראקטיבית, שקופה, אובייקטיבית וקפדנית את תמונת המצב המלאה של מערכת החינוך בישראל לקראת שנת הלימודים תשפ״ז, לנתח את עמדות המפלגות השונות ביחס לסוגיות הליבה, ולהעמיד למבחן ביצוע עובדתי ותקציבי את התחייבויות הממשלה היוצאת.

> [!IMPORTANT]
> **עקרון יסוד אפיסטמי**:
> * **אפס המצאת נתונים (No Hallucination)**: אין להסיק עמדה של מפלגה בהיעדר מקור רשמי חתום ומפורש.
> * **חובת מקור מלאה**: כל פריט מידע פוליטי, תקציבי או עובדתי מעוגן במסמך רשמי מאומת הכולל `sourceId`, סוג מקור, תאריך, רמת אימות ורמת ביטחון.
> * **הפרדה משולשת**: הפרדה דיכוטומית ובלתי-מתפשרת בין **עובדה (fact)**, **ניתוח (analysis)** ו**הערכה (assessment)**.

## 🔗 שרשרת הנתונים (Evidence Chain)

הפרויקט פועל במודל 5 שלבים קפדני:
1. **מקור (Source)**: איתור מסמך רשמי, תיעודו בארכיון ורישומו ב-`sources.json`.
2. **טענה (Claim)**: חילוץ ציטוט אותנטי ומדויק מילה במילה (`verbatimQuote`), ללא כל פרשנות.
3. **עמדה / התחייבות (Position / Commitment)**: שיוך למפלגה הרלוונטית או לקואליציה. אם מפלגה לא התייחסה – אין לייחס לה עמדה.
4. **ביצוע (Execution)**: השוואת ההתחייבות מול נתוני ביצוע תקציביים (חשכ\"ל), סטטוס חקיקה וצווים משפטיים.
5. **הערכה (Assessment)**: ניתוח מקצועי מובחן ומנומק של ההשלכות על מערכת החינוך והרשויות המקומיות לקראת תשפ״ז.

## 🔄 נוהל עדכון והוספת נתונים (Contribution & Update Workflow)

כדי לשמור על אמינות המערכת, כל עדכון או הוספת נתון מתבצעים לפי הסדר הבא:

### שלב 1: שמירת מסמך המקור
הורד ושמור את קובץ המקור (PDF/Word/Excel) בתיקייה הרלוונטית תחת `research/raw/`:
* מצע של מפלגה ➔ `research/raw/party-platforms/`
* הסכם קואליציוני ➔ `research/raw/coalition-agreements/`
* דוח ביצוע תקציב ➔ `research/raw/budgets/`
* דוח למ"ס או מחקר ➔ `research/raw/education-system/`

### שלב 2: רישום המקור ב-`data/sources.json`
פתח את הקובץ `data/sources.json` והוסף רשומה חדשה:
```json
{
  "id": "SRC-MOE-2025-REPRESENTATIVE-ID",
  "title": "שם הדוח הרשמי המלא",
  "sourceType": "official_budget",
  "publisher": "משרד החינוך",
  "publicationDate": "2025-08-20",
  "url": "https://...",
  "localFilePath": "research/raw/budgets/report.pdf",
  "archiveHash": "sha256-hash-value",
  "verificationLevel": "verified_official",
  "confidenceLevel": "high",
  "accessDate": "2026-08-31",
  "language": "he",
  "notes": ""
}
```

### שלב 3: הזנת הנתון לקובץ המתאים
הזן את הרשומה ב-`positions.json`, `commitments.json`, `execution.json` או `education-system.json`, תוך הקפדה יתרה:
* חובה להזין `sourceId` תואם לרשומה שנוצרה ב-`sources.json`.
* חובה להפריד בין הציטוט העובדתי (`verbatimQuote`), לניתוח (`analysis`) ולהערכה (`assessment`).
* חובה להזין `verificationLevel` ו-`confidenceLevel`.

### שלב 4: הרצת בדיקות תקינות
הרץ את סקריפט האימות האוטומטי:
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\validate-data.ps1
```
הבדיקה תוודא שאין מפתחות שבורים, שכל ה-JSONs תקינים סינטקטית ושאין שדות חובה חסרים.

## 🚫 מה לא לעשות בשלב זה
* אל תבנה או תתקין מסדי נתונים כבדים (PostgreSQL, MongoDB וכד'). המערכת מבוססת קבצי JSON וסכמות מקומיות.
* אל תתקין שרתי Backend או שירותי ענן חיצוניים בתשלום.
* אל תמחק קבצים ותיקיות קיימות בתיקיית האב של הפרויקט.
